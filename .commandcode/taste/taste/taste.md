# Taste
- Expects the agent to read the project's onboarding docs (handoff/status) and rules before starting, and to follow all stated project rules. Confidence: 0.65
- Wants the agent to explore and understand the whole project/codebase, not just the files immediately relevant to the task, before implementing. Confidence: 0.6
- Works hands-off on long, multi-step tasks: delegates the plan and then only sends terse nudges ("continue"), expecting the agent to autonomously make operational decisions (run/stop jobs, resubmit, adapt the plan) and keep driving to completion without asking for confirmation. Confidence: 0.6
- Expects project documentation (changelog, lab notes, live-status/activity table) to be kept current as part of every work round, not as a separate cleanup task. Confidence: 0.6
- Expects commits to follow conventional-commit prefixes (feat:, docs:, results:) with a scoped variant when useful, e.g. docs(activity):. Confidence: 0.5
- Versioning convention: release tags are MAJOR.MINOR.BUGS with no leading "v", and they are pushed together with the branch (push --tags). Confidence: 0.5
- Wants code changes gated on the project's own checks before committing: run the test suite (pytest -q) and the linter (ruff check .) and only commit when both are clean. Confidence: 0.6
- New functionality is expected to ship with unit tests (e.g. adding two focused tests alongside a new trainer flag, growing the suite 325 -> 327). Confidence: 0.55
- Prefers new capabilities added as flags/functions in the existing trainer entry point rather than ad-hoc one-off scripts, with a repeated project-level `grep` sanity check on generated launchers (init-from/resume/save-dir) after generating them. Confidence: 0.5
- Prefers fail-fast over best-effort fallback when cluster/GPU capacity is contended: a job picker should refuse (clean exit, "resubmit later") when no GPU has enough free memory rather than falling back to the "least-used" GPU and burning run time on a doomed job. Confidence: 0.5
- Prefers shared, reusable helper scripts over inline duplicated logic across job launchers (e.g. extracting one GPU-picker script that every launcher calls). Confidence: 0.5
- Decides/promotes results on full-sample evaluations only, treating a small fixed in-training guardrail as an unreliable proxy that can diverge from the real metric. Confidence: 0.5
